# Stage: Meeting Transcript Workspace

## Goal
Upgrade Canary Transcriber from diarized transcript export to a meeting-oriented workspace export. When diarization is enabled, the app should generate a structured `.canary.md` that is easier to use as meeting notes: speaker summary table, labeled transcript, and blank follow-up sections for Summary, Decisions, Action items, and Open questions.

## Scope
- Keep the existing `txt` and `json` outputs intact.
- Enhance `.canary.md` when diarization is enabled.
- Add speaker summary data to `.canary.json` for future speaker renaming workflows.
- Preserve the non-diarization path as a simple transcript export.

## Success Criteria
- Diarized transcriptions produce a markdown workspace with:
  - speaker summary table,
  - per-segment speaker labels and time ranges,
  - placeholder sections for meeting follow-up notes.
- `.canary.json` includes speaker summary metadata and empty alias slots.
- `swift build --product canary-transcriber` succeeds after the change.
- README documents the new workspace export behavior.

## Constraints
- Do not regress the current diarization pipeline.
- Do not add a mandatory new UI flow; keep the feature automatic for diarized outputs.
- Keep all user-facing text in English.
- Preserve graceful fallback when diarization returns no segments.

## Risks
- Overly large markdown output for long meetings.
- Divergence between raw diarization labels and future user-renamed aliases.
- Regression risk in embedded Python string formatting.

## Dependencies
- Existing diarization pipeline (`pyannote/speaker-diarization-3.1`).
- Existing `txt/json/md` export path in `Sources/CanaryTranscriber/main.swift`.
- Current README documentation structure.
